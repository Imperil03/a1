# A1 — утверждённая главная

Текущая главная «A1-Интернет Эксперт» — утверждённый вариант **27-team-motion**, перенесённый в корневой [`index.html`](index.html). Это основа дальнейшей работы над сайтом. Прежние визуальные подборки не входят в публикуемый набор.

Релиз предназначен для GitHub Pages: **`main` → `/`**, адрес [imperil03.github.io/a1](https://imperil03.github.io/a1/). Это адрес проекта на Pages. Перенос на коммерческий домен, настройка хостинга и подключение CMS в этот этап не входят. Главная сохраняет `noindex, nofollow`.

Утверждение дизайна, подготовка файлов, успешная публикация и браузерная проверка — отдельные события. Этот документ не подтверждает последние два: их результат, commit и дату записывать после фактического выполнения.

## Структура

```text
index.html                    утверждённая главная
AGENTS.md                     правила работы
DESIGN.md                     дизайн-система и правила разделов
assets/
  css/base.css                общие токены и базовые правила
  css/home.css                композиция главной
  js/navigation.js            навигация
  js/home.js                  поведение главной
  footer-critter/             загружаемая сцена, резерв и лицензии
  …                           изображения, видео, шрифты и их лицензии
tools/footer-critter/         исходник сцены, package.json и lock-файл
prototype/                    внутренние страницы до переноса
  index.html                  совместимый переход к главной
  …                           услуги, компания, кейсы, блог, контакты, цены
docs/                         брифы, источники и исторические решения
```

Главная — статические HTML, CSS и JavaScript. Для её просмотра не требуется сборка всего сайта или запуск Astro. Отдельная сцена футера собрана из React/Three.js; её исходник и lock-файл сохранены для воспроизводимости.

## Локальный просмотр

Из корня репозитория:

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

Открыть [127.0.0.1:4173](http://127.0.0.1:4173/). Использовать HTTP-сервер: открытие через `file://` не заменяет проверку модулей, медиа и путей ресурсов. Если порт занят, выбрать другой свободный порт.

## Сборка сцены футера

Требуются Node.js и npm. Команды выполняются только из каталога исходника:

```powershell
cd tools/footer-critter
npm ci
npm run build
```

Сборка должна обновлять опубликованный комплект в `assets/footer-critter/`. Перед изменением сборки проверить относительный путь `outfile` в `package.json`. Сохранять `scene.js`, загрузчик, резервное изображение и сопроводительные лицензии. Прямое редактирование минифицированного бандла не заменяет изменение исходника и повторную сборку.

## Дальнейшая работа

- Начинать с [`AGENTS.md`](AGENTS.md) и [`DESIGN.md`](DESIGN.md), затем читать текущие файлы затронутого раздела.
- Общие роли менять в `assets/css/base.css`. `--section-heading-gap` задаёт расстояние от заголовочной группы до содержимого; особенности hero, цитаты, контакта, меню и футера описаны в дизайн-системе.
- Сохранять дословный утверждённый контент, назначения действий, полный состав материалов, Onest и статический сценарий.
- Развивать внутренние страницы последовательно. Пока они не перенесены, действующие ссылки главной ведут в `prototype/`; удалять этот каталог при очистке вариантов нельзя.
- При возобновлении продолжать с последнего прямого запроса и текущей главной. Старые планы из брифов не считаются автоматически запрошенными изменениями.

## История и границы релиза

В публикуемом наборе нет `concepts/` с визуальными альтернативами. Более ранние варианты доступны в предыдущих коммитах. Отдельный локальный checkout `C:/Users/Dmitry/Desktop/a1/.work/a1-gallery` остаётся рабочим архивом и не является источником текущей публикации.

Документы в `docs/` могут описывать прежний SEO-прототип, промежуточные пробы, другие технологии и уже отменённые решения. Они нужны как история и источник внутренних страниц. Текущее решение задают корневая главная, `DESIGN.md` и последние указания пользователя.

Само утверждение главной не подтверждает актуальность всех коммерческих данных исходного прототипа и готовность внутренних страниц к переносу на коммерческий домен. Не менять эти данные молча в рамках дизайна; отдельные проверки фиксировать отдельно.

## Проверка выпуска

После подготовки файлов проверить ресурсы, переход со старой главной, ссылки на внутренние страницы, desktop/mobile, меню, медиа, этапы, отзывы, FAQ, футер, клавиатурный фокус и уменьшение движения. Сверить тексты по смысловым блокам с утверждённой версией, включая скрытые состояния.

После публикации проверить именно публичный URL и загруженные версии CSS/JS. В отчёте указывать проверенный commit и фактические результаты. Успех локального сервера или ответ HTTP 200 сам по себе не подтверждает текущую вёрстку и поведение.
