# A1 — SEO-прототип сайта

Репозиторий для проектирования нового сайта веб-студии A1. Студия давно работает в Сургуте и планирует развивать направление в Тюмени. Прототип должен заложить структуру под SEO и дать дизайнеру понятный каркас страниц.

## Что мы делаем

Делаем не дизайн и не production-сайт, а содержательный прототип:

- определяем структуру сайта и URL;
- разбираем поисковые интенты;
- проектируем страницы и порядок блоков;
- готовим тексты и места для доказательств;
- продумываем перелинковку, CTA и мобильный порядок;
- передаём результат дизайнеру.

Техническая основа будущего прототипа — чистые HTML и CSS, небольшой vanilla JS только при необходимости. Фреймворков, сборщика и npm-зависимостей не будет.

## Текущее состояние

- Главная пересобрана в `prototype/index.html` на чистых HTML, CSS и vanilla JS по визуальному и функциональному каркасу первой версии.
- Её структура и карта источников зафиксированы в `docs/pages/home.md`.
- Общая система страниц услуг реализована на четырёх экземплярах:
  `prototype/razrabotka-sajtov/`, `prototype/seo/`,
  `prototype/kontekstnaya-reklama/` и `prototype/complex-marketing/`. Общий
  каркас описан в `docs/pages/service-template.md`, источники страниц — в
  `docs/pages/web-development.md`, `docs/pages/seo-promotion.md`,
  `docs/pages/contextual-advertising.md` и `docs/pages/complex-marketing.md`.
- Четыре основные услуги используют общие токены и компоненты, но получают
  собственную последовательность и от двух до четырёх центральных UX-модулей.
- Самостоятельная страница «О компании» собрана в
  `prototype/company/about/`; её структура и карта источников зафиксированы в
  `docs/pages/about-company.md`. Это редакционная страница с одноколоночным
  нейтральным hero, отдельной лентой фотографий, линейной историей и центральным
  блоком команды, а не вариант шаблона услуги.
- Раздел блога собран как каталог `prototype/blog/`, эталонная статья
  `prototype/blog/neyroseti-v-seo/` и профиль автора
  `prototype/blog/authors/anna-ivanova/`. Каталог поддерживает шесть тематик,
  единую сетку и URL-пагинацию 6 + 4; статья использует компактное оглавление и
  закреплённые слева заголовки глав, а профиль автора содержит опыт,
  специализацию и созданные материалы.
- Общая страница «Контакты» собрана в `prototype/kontakty/`: прямые каналы связи
  доступны на первом экране, адреса Сургута и Тюмени показаны открыто, а маршрут
  можно открыть в Яндекс Картах или 2ГИС. Структура зафиксирована в
  `docs/pages/contacts.md`.
- Старая главная сохранена в `prototype/test/` для визуального сравнения.
- Первая версия задаёт шапку, композицию, кейсы, отзывы, нижний CTA и футер; новый согласованный контент берётся из Word-документа.
- Старый вариант собран через Next.js, но исходников в Git нет. Каталог `_next` нужен только для `/test/`.
- Старая страница услуги удалена; внутренние страницы проектируются заново по
  собственным page brief.
- Ссылки прототипа показывают рабочую навигационную гипотезу и могут вести на
  незаполненные маршруты; они не фиксируют production URL.
- Цифры, цены, кейсы, отзывы и контакты используются как рабочие данные прототипа.
- Формы отправки на главной нет: нижний блок предлагает связаться через предусмотренные каналы.

## Источники текста главной

Используем строгий приоритет:

1. последнее прямое указание пользователя;
2. назначенный пользователем источник конкретного блока;
3. Word-документ с контентом новой главной;
4. первая опубликованная версия и `/prototype/test/`.

Текущий HTML не является источником текста. Видимые фразы нельзя придумывать,
перефразировать или сохранять без соответствия одному из источников. Шесть кейсов
и шесть отзывов перенесены из первой версии дословно; FAQ состоит из пяти
вопросов из Word и трёх вопросов из первой версии.

После публикации:

- новая главная — [imperil03.github.io/a1/prototype](https://imperil03.github.io/a1/prototype/);
- старая версия — [imperil03.github.io/a1/prototype/test](https://imperil03.github.io/a1/prototype/test/).

## С чего продолжать

1. Просмотреть и согласовать страницы блога, «О компании», «Контакты» и четыре
   основные страницы услуг.
2. Подготовить реальные фотографии и сведения для будущих авторов, материалы
   команды и фотографии жизни студии для замены рабочих данных и плейсхолдеров.
3. После отдельного SERP-анализа утвердить production URL для услуг и городов.
4. После содержательного согласования провести общий финальный аудит страниц и
   определить следующий раздел.

Перед любой работой прочитайте `AGENTS.md`.
